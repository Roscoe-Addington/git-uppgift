## G svaret först och VG svaret direkt efter:

- Svar: Versionshantering är ett system eller en metod som sparar olika versioner av ett projekt över tid. Man ser historik i projektet, t.ex. vad som ändrades, varför och när. Den stora skillnaden mellan att spara med sparaknappen och att spara ändringar i Git är: när du sparar med sparaknappen skriver du över den gamla filen, bara den senaste finns. När du sparar i Git med git add plus filnamn och git commit plus beskrivande meddelande sparar du en version av projektet som du kan gå tillbaka till om det behövs. Dessutom kan man skriva beskrivande meddelande om vad som gjordes och förtydliga med prefix (t.ex. chore, docs och feat).

En commit sparar en ögonblicksbild av alla spårade filer som de såg ut i det ögonblicket. En commit är fryst eftersom den inte går att ändra efteråt. Varje commit har ett ID i form av en hash och varje commit pekar bakåt på den förra och tillsammans bygger de en tidslinje. Den första commiten visar fortfarande alla tre TODO, fast filen på datorn har ändrats. Det bevisar att commits är frysta, att nya läggs till utan att ersätta gamla och att historiken är skild från filen.

- Svar: git status visar läget för dina filer, t.ex. ospårade filer, ändrade men ej valda och filer som är redo för commit, kommandot används innan du gör något för att se var du står och efter för att kontrollera, är en livlina. git add stagar vilka ändringar som ska ingå i nästa commit, används efter att man har ändrat och sparat filen i editorn. git commit -m "meddelande" sparar det som har lagts i staging som en ny version med ett meddelande om vad som har ändrats, den används när en särskild ändring har stagats och är redo att sparas.

Relationen mellan arbetsytan, staging och commit är: arbetsytan är filerna i mappen, det man ändrar och sparar, och git add kopierar filen som den är just då till staging. Kopian ändras inte om man fortsätter att redigera filen. Därför kan samma fil både visas som staged och ändrad. git commit sparar det som har lagts i staging som en ny version av projektet med ett meddelande som berättar vad som har ändrats.
Git protesterar med "no changes added to commit" för att den inte kan göra en commit eftersom ändringen inte har lagts till i staging med git add, eftersom commit bara tar med det som ligger i staging.

- Svar: Skillnaden är att mappen på min dator är lokal och i den har man den senaste versionen av projektet och historiken. Repot på GitHub ligger på en server med de commits man har pushat dit och påverkas inte när man gör nya commits på datorn, och andra kan se det om det är publikt. Kommandot git push används för att ladda upp commits som GitHub inte har än.

Båda minnesytorna har en kopia av commit-historiken, och det lokala repot finns på datorn och GitHub-repot finns på en server. De två minnesytorna synkas inte automatiskt och en commit på datorn ändrar ingenting på GitHub förrän man kör git push. Meddelandet "Everything up-to-date" uppstår när det inte finns några nya commits att skicka. Om man har glömt att köra add och commit, så har ändringen varken kopierats till staging eller frysts i en ögonblicksbild genom commit. Git push jämför commits och ser därför inte ändringen, så det finns inget att skicka. Därför är meddelandet inte fel ur Gits synvinkel.
